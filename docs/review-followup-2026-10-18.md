## 专项复核

1. 事务：锁覆盖普通访问，不仅覆盖 tx；所有权在 finally 失效；失败不会阻断后续队列；MySQL 独立连接实现保持不变。
2. 补偿：模型调用在事务外；写入前再次计数，避免重叠 worker 多写；写入与计数更新在同一事务；失败批次允许再次执行；没有剩余工作时不会因本轮产量为零误判失败。
3. 版本：保留现有只读/可编辑状态限制、内容 hash 去重、恢复接口与权限；没有增加一套版本存储。
4. 心跳：定时器 unref，不阻塞进程退出；关闭等待在途写入后删除，避免先删后续期留下假活跃键；异常退出仍依靠 TTL 清理。

## 真实环境验收与边界

尚未连接真实 MySQL、Redis、模型服务或运行完整浏览器端到端流程。DDL 静态检查不能替代 MySQL 事务实跑，虚拟时钟测试不能替代 Redis/BullMQ 联调，服务层恢复测试不能替代页面点击验收。

建议在测试环境依次验收：

1. 双人选题并发送入；模拟第二次 copy 插入失败，确认 assigned 与零残留，再重试成功。
2. `countPer > 1` 的生成任务中途终止 worker，重启后确认缺额补齐、已成功组合不重复、produced 等于实际条数；验证 MySQL 批次行锁与 BullMQ stalled/attempts。
3. 真实模型返回不足条数或调用失败，确认批次失败可见且队列重试补齐；重试耗尽后需人工重新入队，不增加无限重试机制。
4. 编辑稿件，等待自动保存完成，再点保存草稿；打开历史版本并恢复旧版本，刷新后确认内容与 restore 记录；审核中不可编辑。
5. 运行超过 30 分钟后以同前缀、不同数据库启动第二实例，确认警告；正常关闭后注册消失，强杀后 TTL 到期清理。
6. 用实际人物规则和真实口播样本验收预检，再走生成→编辑→预检→提交审核流程。规则扫描仍为原架构的词组匹配，不承诺完整语义合规判定。

历史上已标 sent 但缺失 copy 的异常记录没有自动修复，避免猜测应创建的人物集合；本次确保新的送入原子性。历史上已标 done 的不完整批次保持终态保护，需要先核对数据再人工重置批次状态并重新入队。

copy_contract 创建的是 topic 对应的 copy 创作单元；空白 copy_draft 仍沿用现有提交后初始化及 detail 懒建机制。本次没有把该初始化副作用迁入跨模块事务。
