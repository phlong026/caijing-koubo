### 0.2 本模块决策（v1.0 拟定，待评审拍板）

| # | 决策 | 内容 | 备注 |
|---|---|---|---|
| EC1 | 版本模型 | `video_cut` 一行 = 一个成片版本：`(video_job_id, version_no)` 唯一，正式版本 version_no 从 1 单调递增（取号 + 插入同事务、撞 UNIQUE 重试，沿视频创作 §3.2 模式）；**草稿为固定 `version_no=0` 的特殊行**（每 base 至多一个，upsert 语义恰由唯一约束保证）。「渲染」= 读取 draft 配置**新建一行** queued 版本，draft 保留可继续编辑；历史版本只读 | 对齐视频创作「重新生成永远新建版本」（V1）；发布 `publish_plan.base_video_version_no` 的引用模式 |

| EC3 | 字幕形态 | 句级字幕：base 时间轴 `TimelineItem[]` 每句一条（一期不做字级 KTV / 关键词特效）；超长句按「中文每行 ≤20 字、最多 2 行」换行（平移 AI-Studio `extractLines`）；字幕文本默认取时间轴原文，normal 段可编辑、risk 段锁定 | 句级时间轴已随 base 落库，无需 AI-Studio 字级分组（`groupAndAllocateSubtitles` 不平移） |
| EC4 | 字幕渲染方案 | ASS 文件 + `ass` 滤镜 burn-in（平移 `createASSSubtitle`），**PlayRes 修正为竖屏 1080×1920**（AI-Studio 原版 1920×1080 横屏）；字体走 `fontsdir` 指向仓库内置开源字体目录（思源黑体，OFL 授权），不依赖系统字体与 fontconfig；样式字段白名单校验 | AI-Studio 的 drawtext 逐条兜底路径不平移（Windows 盘符转义与字体路径逻辑重）；`subtitles` 滤镜不用（ASS 已含样式） |

| EC6 | BGM 一期轻量库 | 不等素材库模块：`GET/POST /cut/bgm`（admin 上传 mp3 → OSS `bgm/`）；混音 = BGM 循环裁剪到视频时长（真实 `probeMedia` 时长）+ 淡入淡出 + `volume` + `amix=inputs=2:normalize=0`（**关闭 amix 默认归一化，否则口播被自动减半 -6dB**——AI-Studio `VideoBGM.ts` weights 缺陷之外的第二个坑）+ `alimiter` 防爆音；口播音轨以 **48kHz 立体声**专用提取（不复用 `extractAudio`——它固定 16kHz 单声道，为 ASR 设计，直接混音会把成片音频压到电话音质） | 素材库立项后迁移其「声音库」；音量默认 0.2 |
| EC7 | 风险尾页 | 默认启用；文案 = base `riskText`（textSnapshot risk 段拼接，**锁定不可编辑**）；样式黑底白字居中；时长默认 5s（`risk_tail_seconds` 可配，1~15s）；渲染 = `color` 底 + `drawtext`（自动换行）生成片段（同分辨率 / 帧率 / 静音轨）→ concat 到成片末尾；mock 引擎下为纯黑片段；尾页时长不计入字幕时间轴 | 满足 A4；「适用范围待业务确认」→ Q4 |
| EC8 | 渲染流水线 | 固定顺序：下载 base → 剪气口（可选）→ 字幕烧录（可选）→ BGM 混音（可选）→ 尾页拼接（可选）→ `normalizeGeneratedVideo` 规范化 + 首帧封面 → 上传 OSS `video-jobs/{jobId}/cuts/{versionNo}/` → CAS completed → 清理临时目录。一期分段实现（≤5 次重编码），合并 filter 链优化后置（§10 R2） | 复用 mixcut `compose.ts` 的 argv 拼装与归档上传范本 |
| EC9 | 成片复审链 | 新表 `cut_review_submission`，状态机对照文案审核链（`submitted→gate1→gate2→gate3→pending_manual→approved/rejected`，逐关 CAS）；**桩推进为同步无间隔**（文案链的 `REVIEW_STUB_STEP_MS` sleep + `is_stub` 重启续推机制不平移——同步推进在提交请求内完成，无中途停摆窗口；异常中间态单在重新提交时废弃重开）；第 1 关合规模板扫描**只读复用**文案审核链的合规模板数据（不改其表），扫描对象为字幕文本 + 尾页文案，命中记 risk_points 仍进 pending_manual 供人工重点核；第 2 关审核智能体桩（HTTP 对接同文案链路后置），第 3 关校验风险尾页存在；人工裁决 reviewer/admin（`ROLE_RULES` 显式注册）；rejected 后同版本不可重复提交（409，须改配置重渲新版本） | 不改文案 `review_submission` 表（版本粒度不同，避免语义混用）；列名以本任务书 §4.1 为准 |
| EC10 | 实质修改联动 | `content_hash` = SHA-256(base_version_no + 字幕文本序列 + 尾页文案 + 归一化参数)；提交复审通过时冻结 `approved_content_hash`；之后任何配置变更使 hash 变化 → 成片 `review_status` 重置 `none`（需重新渲染 + 复审）；发布取用契约校验 `content_hash == approved_content_hash` | 对齐 A2 与发布 FR-R2 语义；「未复审不可发布」在 final 契约层硬拦截 |
| EC11 | 发布对接 | `GET /video-cuts/:id/final` 输出**含发布消费字段（`cutId, videoJobId, versionNo, copyId, copyVersionId, copyVersionNo, url, coverUrl, durationMs, width, height, timeline, reviewStatus, isMock`）的同形 payload**（非视频创作 FR-X1 全量同构——发布侧当前仅消费 url/coverUrl/durationMs/copyVersionId + copyId 校验）。发布侧改动面为**三处**（不止 plans.ts）：① `plans.ts` 创建时取输入优先成片回落 base，`videoJobId` 转可选（缺省 = copy 下最新过审成片，无则报 `VIDEO_NOT_READY`；显式给出 = 该 job 的过审成片，无则回落该 base）；② `execute.ts` 上传文件来源按计划实际输入版本取 `video_cut.result_key`、回落 `video_job.result_key`（**只改 plans.ts 会出现「计划记成片、上传发 base」的静默错发**——execute.ts:85-102 现直接读 video_job）；③ `routes.ts` 放开 videoJobId 必填校验。不改 publish 表结构（`base_video_version_no` 语义升级为「发布输入版本号」） | 发布 PB4 升级落地；发布任务书 §14 追加注记 |
| EC12 | 预览方案 | 一期前端低仿预览：`<video>` 播放 base 签名 URL + CSS 字幕叠加（按时间轴与样式实时渲染）+ 尾页占位；成片渲染完成后切 `<video>` 回放成片。不做服务端预览帧渲染 | 原型即此方案；保证「所见即所得」差异由成片回放兜底 |
| EC13 | 并发与超时 | 渲染队列 `video-cut` 并发默认 2（`CUT_WORKER_CONCURRENCY`）；单步 ffmpeg 超时 600s（沿 `compose.ts`）；整任务卡死兜底：`videoCutSweep` 60s 扫描 `rendering` 超 30 分钟无进展 → failed(`CUT_RENDER_TIMEOUT`)；重启 reconcile：queued / rendering 重投 | 同视频创作 sweep 模式 |
| EC14 | 剪辑入口 | 视频创作 `nextActionsOf` 已返回 `continue_edit`（`VideoCreate.vue` 现有「进入视频剪辑」按钮为硬编码 phase 判断，改造为按 nextActions 驱动）；query 参数统一 `?videoJobId=`（与视频创作既有跳转约定一致），路由 `/video/edit`；base 不可用时入口置灰 | 发布 FR-X2 遗留的「去发布」前端入口随本模块 CE6 一并补（见 §12 发布管理行） |

## 1. 范围

### 1.1 一期做

- **剪辑配置与草稿**：取 base 时间轴初始化配置；字幕分段编辑（normal 可改 / risk 锁定）、字幕样式（字体 / 字号 / 颜色 / 描边 / 背景 / 位置 / 对齐）、BGM（选择 / 音量 / 淡入淡出）、剪气口（开关 + 参数）、风险尾页（开关 + 时长）；草稿保存与恢复。
- **成片渲染**：`video-cut` 队列 worker；CutRenderEngine（ffmpeg / mock）；§3.4 流水线；进度回报；取消；失败重试；sweep 兜底与重启续跑。
- **成片复审**：提交复审；三关桩自动推进；人工通过 / 退回（原因必填）；实质修改自动置回待复审；审核工作台成片队列（按线筛选）。
- **发布对接**：`GET /video-cuts/:id/final` 契约；发布模块取输入优先成片；「去剪辑」入口。
- **前端**：`VideoEdit.vue` 整页重写（替换静态演示）；审核工作台成片 Tab 扩展。
- **环境基座**：`check-media-env` 滤镜探测；内置开源字体；轻量 BGM 库。

### 1.2 一期不做（边界）

- 字级 KTV 特效、关键词特效、标题字幕、多字幕轨道（AI-Studio `DrawtextGenerator` 1626 行特效库不平移）
- 字幕时间手动调整、字幕分段增删（只改文本；句级结构由文案与时间轴决定）
- 画中画（A9，技术方案注记见 §12）、封面模板化设计（AI-Studio Python 渲染链不平移；封面 = 首帧 `extractCoverFrame`）
- 字幕样式模板库（16 套系统模板不平移；一期单一默认样式 + 自定义参数）
- 剪气口 jumpcutter Python 路径；变速剪气口（silence_part_speed）
- 服务端预览帧渲染；BGM 推荐与自动匹配（AI-Studio `calculateMatchScore` 为假实现，弃用）
- 成片多分辨率输出（一期固定 1080×1920）；字幕字体在线预览渲染图

## 3. 状态机、规则与算法

### 3.1 video_cut 状态机

```
draft(version_no=0, upsert 唯一, 不参与版本序列) ──创建渲染──→ 新建行 queued（draft 保留可继续编辑）
queued ──worker 领取──→ rendering ──┬→ completed
   └─cancel→ cancelled             └─cancel→ cancelling ──┬→ completed（取消晚于末检查点，完成当前步骤后照常落 completed，记事件「取消未及」）
        cancelling 中步骤失败 ─→ failed                   └→ cancelled（sweep 兜底：cancelling 超 10 分钟无进展）
failed ──retry-render──→ 新建行 queued（复用配置，version_no 续号）
completed 之后：review_status ∈ none → in_review → approved / rejected（FR-V3 重置）
rendering 内子阶段 render_stage：download → breathe → subtitle → bgm → tail → normalize → uploading（进度权重见 §3.6）
```

- 状态迁移一律 CAS（`WHERE id=? AND status=?`），沿 `casTransition` 模式；取消检查点在 §3.4 各步骤之间，末检查点（normalize 开始）后的取消请求不再中断，落 completed 并记事件。

### 3.2 cut_review_submission 状态机（成片复审）

```
submitted ──桩──→ gate1(禁用词扫描) ──桩──→ gate2(智能体桩) ──桩──→ gate3(尾页校验) ──→ pending_manual
     └────────────────── 任一关硬失败(一期桩不触发) ──→ rejected
pending_manual ──人工──→ approved（冻结 approved_content_hash）
              └─人工──→ rejected（原因必填）
```

- 三关推进为**提交请求内同步 CAS**（无 sleep 间隔，无 `is_stub` 续推需求——与文案链的异步桩 + `resumeStubSubmissions` 机制不同，见 EC9）；每关结果写 `gates` json（关名 / 结论 / 命中项 / 置信度占位）；异常中间态单（submitted/gateN 遗留）在同版本重新提交时废弃重开。

### 3.3 实质修改判定

```
content_hash = SHA-256(
  base_version_no │ segments[].index+text │ risk_tail_text │ risk_tail_seconds │
  subtitle_style 归一化 │ bgm 配置归一化 │ breathe 配置归一化 │ subtitle_enabled 等开关
)
```

- 归一化 = 键排序 + 去空白 + 数值统一字符串；仅「无效果开关全关」时样式 / BGM / 剪气口参数不参与 hash（改了也不触发复审）。
- 过审后保存草稿使 hash 变化 → `review_status` 重置 `none`（FR-V3）；final 契约硬校验（FR-X1）。

### 3.4 渲染流水线（worker 单事务外逐段执行）

```
0 download downloadObjectToFile(base.result_key) → resolveJobTempDir(tempRoot, cutId)/base.mp4（进度 0→5）
1 breathe  (启用，mock 下照跑) silencedetect(noise=NdB:d=ms) → keepSegments → 分段 -ss/-to 重编码(libx264 CRF18)
           → concat demuxer 拼回 → remapTimeline(timeline, keepSegments)
2 subtitle (启用) buildAss(segments×timeline, style, fontsdir=内置字体) → -vf ass=... 烧录（CRF18）；mock 降级为转码直过
3 bgm      (启用) 口播音轨 48kHz 立体声提取 + BGM loop/cut → afade → volume → amix(normalize=0) → alimiter → 回贴(-c:v copy)
4 tail     (启用) color 黑底 drawtext 白字(fontfile) + anullsrc 静音轨，-r/-s/pix_fmt 对齐 → concat；mock 降级为纯黑片段
5 normalize normalizeGeneratedVideo(1080×1920 / H.264 / AAC) + extractCoverFrame
6 upload   putObjectFromFile(video-jobs/{jobId}/cuts/{versionNo}/final.mp4 + cover.jpg)
7 落库     CAS rendering→completed：result_key/cover_key/duration_ms/timeline/content_hash/progress=100 → 清理临时目录
```

- 每步产物写临时目录下一步复用；取消检查点在每步之间（§3.1）；任一步失败 → failed + 清理。
- mock 引擎仅降级**第 2 / 4 步文字渲染**（字幕直过、尾页纯黑）；剪气口（第 1 步）与 BGM（第 3 步）照跑，保证 AC-R1 / AC-R2 / AC-B2 可在 mock 全链路自动化验收，`is_mock=1`。

### 3.5 剪气口与时间轴重映射

```
silence 段 S = silencedetect 输出（合并相邻，间隔 < keepGapMs 的静音不剪）
keepSegments K = [0..duration] − S，且相邻句间至少保留 keepGapMs
remap: newT(t) = K 中定位 t 所在段 Ki → Ki.start' + (t − Ki.start)；K 前缀累计偏移预计算 O(n)
句级 TimelineItem 整体落位：startMs/endMs 分别映射；跨段句（理论上不出现，句间隙≥keepGapMs）取段边界截断
```

- 纯函数 `remapTimeline(timeline, keepSegmentsMs): TimelineItem[]` + `buildKeepSegments(durationMs, silences, keepGapMs)`，vitest 单测覆盖：无静音 / 全静音 / 句中静音 / 边界重合。

### 3.6 进度权重

| 阶段 | download | breathe | subtitle | bgm | tail | normalize | uploading |
|---|---|---|---|---|---|---|---|
| 占用进度区间 | 0→5 | 5→20 | 20→55 | 55→75 | 75→85 | 85→92 | 92→100 |

- 单调不回退（沿 `progress.ts computeJobProgress` 模式）；阶段开始即推进到区间起点，结束推到终点。

## 10. 前置条件与风险

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| R1 | **ffmpeg 缺 libass / freetype**（已实测：本机 ffmpeg 9.0.2 无 `ass`/`subtitles`/`drawtext` 滤镜） | 字幕烧录与尾页文字不可用 | EC2 渲染引擎 mock 兜底 + AC-0.2 探测；**部署清单要求 ffmpeg 带 `--enable-libass --enable-freetype`**（brew install ffmpeg / apt ffmpeg 标准构建均含）；真实渲染列入人工验收 |
| R2 | 多次重编码画质与耗时 | 5 段式流水线对 180s 视频约 2~5 分钟（并发 2） | 一期接受（短视频 + 离线队列）；二期合并 filter_complex 单命令优化；进度可见 |
| R3 | 剪气口误剪 | 爆破音 / 气声被判定静音，或剪后节奏生硬 | 保守默认（-30dB/500ms）；开关默认关；keepGapMs 保底；效果人工抽验列入验收 |
| R4 | 时间轴精度 | estimated 时间轴剪字幕会漂移放大观感问题 | 配置页提示「建议先在视频创作执行重新对齐（realign）」；timelineSource=estimated 时前端警示 |
| R5 | 素材授权 | 服务端无系统中文字体（随意下载有商用授权风险）；BGM 曲库版权同样未定 | 内置思源黑体（SIL OFL）；上传字体与授权标记列素材库范围；**BGM 一期要求运营自备可商用曲库并在名称标注来源**（Q1 随拍板确认），素材库立项后并入授权标记体系 |
| R6 | 字幕编辑与过审文案漂移 | 改字幕不改文案 → 视听不一致绕过文案审核 | risk 锁定 + 实质修改复审联动（EC10）+ 复审单展示字幕 diff（FR-V4）；审核口径写入 §11 Q5 |
| R7 | ASS 竖屏适配失真 | AI-Studio 生成逻辑为 1920×1080 横屏，PlayRes / 边距 / 字号比例需按 1080×1920 重调 | 平移时参数化 + 真机抽帧验收（AC-S3）；字号默认值按竖屏重标定 |

### 14.2 与任务书的差异

1. **组件拆分收敛**：任务书 §7 预列 7 个子组件（SubtitleList / StylePanel 等），实际为控制单文件复杂度将面板内聚在 `VideoEdit.vue` 内（页长约 470 行，分区块注释），对外行为与任务书规格一致；后续如需复用再拆。
2. **「去剪辑」入口复用存量**：`VideoCreate.vue` 已有「进入视频剪辑」按钮（并行任务中心工作线同日追加了「去发布」入口）；为避免与并行会话在同一文件冲突，未改造为 nextActions 驱动（FR-X3 的行为差：按钮现为 phase 硬编码判断，语义等价），改造点留待并行线合入后统一处理。
3. **`/media/*` 白名单放宽为前缀包含式**（`^(.*\/)?(video-jobs|material|bgm)\/`）：本地 OSS 兜底会拼接全局 `OSS_PREFIX`（默认 `benchmark-audio/`），精确头匹配会 403 掉本地回放，故改为允许任意前缀下的三类受限目录。
4. **normalize 达标透传**：`normalizeGeneratedVideo` 校验通过时不写目标文件（源即产物），渲染管线以 `transformed` 标志选择上传源——任务书 §3.4 第 5 步的实现级澄清，非行为变更。
5. **FR-V3 漂移基准**：成片行 content_hash 冻结于渲染时，实质修改判定按「草稿行（version_no=0）content_hash vs 成片 approved_content_hash」实现（§3.3 语义的实现载体），final 契约同口径拦截。
