### 0.2 本模块决策（v1.0 拟定，待评审拍板）

| # | 决策 | 拟定结论 | 理由 |
|---|---|---|---|
| V1 | 对象分层 | **视频任务（video_job）= 一次基础视频生成**，绑定 `copy_id + copy_version_id + persona_id + persona_version_id + 配置快照`；同一 copy 下 `version_no` 单调递增，界面显示「基础视频 v1/v2」。重新生成**永远新建版本**，旧版本保留（不覆盖）。剪辑、发布绑定的是**某个已完成的 video_job** | 对齐效果图「基础视频 v1 → 剪辑 v2」与文案工坊 W2/W5 的「不覆盖」口径；人物库 L7 要求视频任务绑定人物版本 |
| V2 | 引擎抽象 | 服务端只定义一个适配器 `AvatarVideoEngine`，实现为 `hifly`（真实）与 `mock`；`provider` 字段保留以备二期。生成方式 `gen_mode`：**`tts`（默认）= `video/create_by_tts`**，以人物克隆声音 `vendorVoiceId` + 口播全文 + 分身 `vendorAvatarId` 由飞影**一次直接成片**；`audio` = `video/create_by_audio`（先得到整轨音频再驱动口型），仅在 §11 Q3 选 B 时启用。**不再有独立的 TTS 引擎**：口播的语音合成在飞影侧完成；混剪配音用飞影 `audio/create_by_tts`。一律经人物库共享的飞影客户端（A13），不引入众墅之家的钱包 / 预扣计费 | 飞影 `create_by_tts` 一次调用即出带声音的口播视频，省掉「本地 TTS → 上传 → 驱动」三段；与人物库同一套客户端与错误分类 |
| V3 | 阶段状态机 | 平移众墅之家 `oral_tasks` 的状态语义（`QUEUED → SUBMITTING → RUNNING → ARCHIVING → SUCCEEDED`，异常 `FAILED / SUBMISSION_UNCERTAIN / ARCHIVE_FAILED`）与 `oral_worker.py` 的 `task_submit / task_poll / task_archive` 三类工作，映射为本模块阶段（§3.1），并增加 `aligning`（时间轴）与混剪的 `tts / composing`。**状态以数据库为准**，队列只负责推进；阶段迁移一律 CAS；进程重启按 `reconcile` 规则续跑 | 众墅之家该链路已在生产处理过「提交结果未知」「成片已出但归档失败」「轮询超时」等真实故障 |
| V4 | 生成与保存解耦 | 飞影已出成片但下载 / 校验 / 入库失败 → `save_failed`（= `ARCHIVE_FAILED`），只允许「重试下载」，**禁止重新提交**；创建请求已发出但没拿到飞影业务码或 `task_id`（网络中断 / 超时，`HiflySubmissionUncertain`）→ `submission_unknown`（= `SUBMISSION_UNCERTAIN`），**不自动重提**，须人工核对。有明确业务码的拒绝才判 `failed` | A8；与人物库 L9、爆款选题 `uncertain` 同一原则，杜绝重复扣积分 |
| V5 | 轮询方式 | 远端生成期间**不占用 worker**：提交拿到 `task_id` 后 job 结束，由 `video-poll-sweep`（每 10 秒）扫描 `phase IN (generating, recovering) AND next_poll_at<=now` 的任务逐个调 `video/task`；查询异常或状态未知按 5/10/20/30 秒退避、继续等待。距提交超过 **2 小时**（`HIFLY_POLL_MAX_AGE_MS`，同众墅之家 `ORAL_MAX_POLL_AGE_SECONDS`）仍非终态 → 转 `submission_unknown`（`VIDEO_POLL_TIMEOUT`）人工核对，**保留飞影任务号，绝不自动付费重试** | 生成耗时随口播时长变化（PoC 实测）；阻塞式轮询会占满并发槽 |
| V6 | 口播文本与时间轴 | 口播文本 = 已通过版本各段正文 + 风险话术（`riskHint`，作为最后一段并标 `kind=risk`），按原顺序以换行拼接后**整段**提交 `create_by_tts`（≤10000 字）；**不让飞影烧录字幕**（`st_show=0`，字幕在剪辑模块添加，A7）。飞影返回的成片**不带分句时间戳**，句级时间轴改为**成片后 ASR 对齐原文**（§3.4）：对成片音轨做百炼 ASR，只借用识别结果的时间戳，**字幕文本永远取过审原文**（ASR 错字不进入时间轴）；对齐质量不达标或 ASR 失败时，按字数比例估算并标 `timeline_source=estimated`，基础视频照常完成，可「重新对齐」。备选方案见 §11 Q3 | 剪辑屏的字幕时间段须来自生成环节；「过审文本不可变」——ASR 只提供时间不提供文字；视频已付费生成，时间轴问题不应让任务失败 |
| V7 | 人物资产来源 | **不再建本模块的人物资产桩**（原 `persona_asset` 桩删除）。可用分身、声音、授权一律以人物库为准：预检合并 `readiness`；创建时取 `production-profile`（可带 `?avatarId`）并整体冻结进配置快照；**提交飞影前再取一次**，声音参数或分身 / 声音标识与快照不一致时 `failed(VIDEO_PERSONA_CHANGED)`、不调用飞影。人物库 PL5 交付前，本模块用与 FR-X5 同形的 fixture 实现开发与 smoke，接口不变 | 人物库已承担分身 / 声音 / 授权全流程（A12）；声音的语速 / 音量 / 音调存在飞影侧（人物库 FR-V6），排队期间被改会导致成片与快照不符 |
| V8 | 背景的含义 | 飞影分身**背景随源视频固定**（A14、人物库 L15）。一期「背景」下拉 = 该人物 `ready` 分身列表（显示各分身的 `backgroundLabel`，如「白色简洁」），切换背景即切换分身，经 `production-profile?avatarId=` 取用。人物库的背景图 / 背景视频 / 空镜只作为**混剪底板**使用，不参与飞影生成；独立换背景不在一期 | 不承诺做不到的抠像换背景 |
| V9 | 混剪一期范围 | 混剪 = 「配音整轨 + 底板画面（人物背景 / 空镜循环）+ 按时间轴的素材覆盖」。配音由飞影 `audio/create_by_tts` 整段合成（经理 / KOS 用人物默认声音；素人线见 §11 Q12），时间轴同 V6 用 ASR 对齐原文得到。一期做**关键词模式**（平移 `KeywordModeProcessor.processFromRecords` + `FFmpegCommandBuilder`）；**语义向量匹配**与「产品替代」不在一期 | 技术方案 5.4「先关键词后语义」、5.5 产品替代需 PoC |
| V10 | 配置检查（硬/软） | 硬项：①文案已通过且取到版本 ②人物 readiness 硬项全过（口播 `purpose=avatar_video`：启用、授权有效、默认分身 ready、默认声音 ready 且已确认、飞影已配置；混剪 `purpose=mixcut` + 有可用配音声音）③模式允许（素人线禁用口播）④所选分身属于该人物且 `ready` ⑤口播时长 ≤ 上限且文本 ≤10000 字 ⑥飞影已配置（或 MOCK）⑦混剪时素材包可用。软项：⑧飞影积分余额低于本次预估消耗 ⑨已通过版本不是最新提交（文案修订中）⑩已存在进行中的同配置任务 ⑪分身源视频非 9:16（成片将补边） | 对应效果图「配置检查：文案 v3 已通过人工复核 / 形象与声音已绑定 / 人物背景已配置」；授权与声音确认以人物库判定为准，本模块不重复判断 |
| V11 | 文案更新后的旧视频 | 文案重提通过产生新版本后，已有基础视频**不自动失效**，界面标注「基于文案 v3，最新已通过为 v4」，允许按新版本重新生成；剪辑/发布模块据此做提示 | 与 A3 一致；是否强制失效由发布前复审把关 |

## 1. 范围

### 1.1 一期做

- **取稿与入口**：从文案工坊「去视频创作」带 `copyId` 进入；无 `copyId` 时选择已通过文案；展示文案卡（标题 · 人物 · 线 · 文案 vN · 字数 · 预计时长 · 审核结论）与「查看文案」
- **数字人口播**：选口播分身（即背景）、查看并试听人物默认声音、配置检查；提交飞影生成；进度；结果预览；重新生成（新版本）
- **素材混剪**：选素材包与关键词组、底板（人物背景 / 空镜）、配音声音；按时间轴自动覆盖素材；产出基础视频
- **生产执行**：飞影 `create_by_tts` 直接成片（`create_by_audio` 为 Q3 备选）、`video/task` 轮询、下载 / 规范化 / 校验 / 归档、成片后 ASR 对齐时间轴；阶段状态机、重启续跑、`save_failed` 重试下载、`submission_unknown` 人工核对、2 小时超时转人工、取消 / 停止等待
- **人物资产取用**：消费人物库 `production-profile` 与 `readiness`，冻结进任务快照；向人物库提供「是否被进行中任务引用」查询（软删守卫）
- **素材包桩**：素材包（文件夹/压缩包导入）与关键词组的最小管理（供混剪）
- **对接契约**：上游取稿；下游「基础视频取用」契约（给视频剪辑）、任务中心状态字段、文案工坊步骤条「视频创作」节点
- **可观测与成本**：每次飞影 / ASR 调用写 `api_call_log`；任务记录预估积分、耗时、阶段历史；`operation_log`

### 1.2 一期不做（边界）

- 字幕烧录、字幕样式、BGM、剪气口、画中画、**风险尾页**、成片复审（视频剪辑模块）
- 发布与平台账号（发布管理模块）
- 口播分身制作、声音克隆、声音参数调整、授权材料核验（人物库 M1；本模块只读取其结果）
- 素材库正式页面、素材自动打标与**语义向量匹配**（素材库 / 二期）
- 分身换背景（飞影不支持，A14）、产品替代（PoC 后另立）
- 飞影以外的数字人服务商、自建 GPU 数字人（不在一期；`provider` 字段为二期预留）
- 飞影积分精确对账（一期只记预估积分与调用记录）
- 封面设计（剪辑 / 发布模块；本模块只抽取首帧作为预览缩略图）

### 2.4 生产执行（服务端）

| FR | 需求 | 细则 |
|---|---|---|
| FR-P1 | 口播文本快照 | 由 `approved.sections` + `riskHint` 生成：每段按句末标点（。！？；…及换行）切句，句长 >`VIDEO_SENTENCE_MAX`（默认 120 字）再按逗号切（切句只用于时间轴，不改变提交文本）；风险段标 `kind=risk`。快照字段：`segments[{index, sectionIndex, kind, text}]`、`submit_text`（各段原文按顺序以换行拼接，**逐字等于过审原文 + 风险话术**）、`text_hash`（规范化后 SHA-256）。`submit_text` >10000 字（飞影上限）或总口播时长预估 >`VIDEO_MAX_SECONDS`（默认 180）拒绝（`VIDEO_TEXT_TOO_LONG`） |
| FR-P2 | 提交（`task_submit`） | 平移众墅之家 `oral_worker.py` 的 `task_submit` 与 `oral.py#create_oral_task` 提交段：`preparing`——重取 `production-profile?avatarId=`，`vendorAvatarId / vendorVoiceId / 声音参数` 与快照不一致 → `failed(VIDEO_PERSONA_CHANGED)`，人物不再 ready → `failed(PERSONA_NOT_READY)`，均**不调用飞影**；`submitting`——**事务外**调 `createVideoByTts({voice: vendorVoiceId, text: submit_text, avatar: vendorAvatarId, title: vendor_title, aigc_flag: 1, subtitle: {st_show: 0}})`，拿到 `task_id` **立即 CAS 落库**（`WHERE id=? | FR-P4 | 下载与归档（`task_archive`） | 平移众墅之家 `oral_worker.py#task_archive` 与 `oral.py#_archive_oral_result`：`downloading`——`video_Url` 须过**结果域名白名单（`HIFLY_RESULT_HOSTS`，PoC 记录实际域名）+ https + DNS 解析非内网 + 跳转 ≤3** 校验（防 SSRF），流式下载，上限 `VIDEO_ARCHIVE_MAX_MB`（默认 512MiB）；地址已失效（403 / 404）时先重调 `video/task` 取新地址再下载，**不重新提交**；`verifying`——ffprobe 校验有视频流与音频流、时长 >0 且与飞影 `duration` 偏差 ≤1 秒（偏离字数预估 ±40% 只记警告）；按 `normalize_generated_video` 规范化：等比缩放不裁切、补边到 1080×1920、H.264 / AAC / 30fps / `+faststart`；抽首帧作为缩略图；上传 OSS → CAS 更新（`WHERE id=? | FR-P5 | 时间轴对齐（`aligning`） | 归档完成后执行（§3.4）：ffmpeg 抽出成片音轨（16kHz 单声道）→ 上传 OSS 取签名 URL → 百炼 ASR（复用 `integrations/dashscope/asr.ts`，扩展返回字 / 词级时间戳）→ 与 `segments` 原文做字符级对齐 → 输出 `timeline[{index, kind, text(原文), startMs, endMs}]`、`align_score`。`align_score ≥ VIDEO_ALIGN_MIN_SCORE`（默认 0.85）→ `timeline_source=aligned`；否则或 ASR 失败 → 按字数比例在 `[0, 成片时长]` 内估算、`timeline_source=estimated`、写 `video_job_event` 警告；两种情况任务都进入 `completed`。「重新对齐」（`POST /video/jobs/:id/realign`）只重跑本步，不调用飞影。`gen_mode=audio` 时时间轴来自分句实测（`timeline_source=measured`），跳过本步 |
| FR-P6 | 重启续跑 | 进程启动时按 `reconcile` 规则处理所有非终态任务（平移众墅之家 `_quarantine_expired_submissions` 的判定，租约改为阶段 CAS）：`preparing`（未调用飞影）回 `waiting` 重新排队；`submitting` 有 `remote_task_id` → `generating` 续查，无 → `submission_unknown`（「供应商提交结果未知，已停止自动重试」）；`generating / recovering` → 续查（超时规则照常）；`downloading / verifying` → 重新下载一次（下载不计费；再失败则 `save_failed`）；`aligning` → 重新对齐；混剪 `tts`（已有飞影任务号则续查、无则按缓存身份重来）/ `composing` → 重新合成（配音复用） |
| FR-P7 | 取消 | `waiting / preparing` 可取消（`cancelled`）；`submitting` 不可取消（等待其结果）；`generating` 之后只能「停止等待」→ `paused`（飞影无取消接口，积分照扣），可随时「继续查询」→ `recovering`；混剪 `tts / composing` 可取消（已合成的配音保留并可复用） |

## 3. 状态机、规则与算法

### 3.1 video_job 阶段机（平移众墅之家 `oral_tasks` 语义，增加 `aligning` 与混剪阶段）

```
数字人口播（默认 gen_mode=tts，video/create_by_tts）：
 waiting ─→ preparing ─→ submitting ─→ generating ─→ downloading ─→ verifying ─→ aligning ─→ completed
    ↑            │            │   │          │   ↑          │              │          （对齐失败也 completed，
    │ 1001/1015  │ 人物变更    │   │ 无业务码  │   │ 查询异常  └──────┬───────┘           timeline_source=estimated）
    └────────────┼────────────┘   │ / 超时    │   │ / 重启           ↓
                 ↓                ↓          │ recovering      save_failed ──重试下载──→ downloading
              failed ←─业务码─  submission_unknown ←── 超过 2 小时（VIDEO_POLL_TIMEOUT）
                 ↑               （人工：查询原任务 / 补录任务号 / 确认未提交后重提 → preparing）
                 └──────── 飞影 FAILED

备选（gen_mode=audio，Q3=B）：waiting ─→ tts ─→ uploading ─→ submitting ─→ generating ─→ …（同上，跳过 aligning）

素材混剪：waiting ─→ tts ─→ aligning ─→ composing ─→ verifying ─→ completed（tts/composing/verifying 失败 → failed；配音可复用）

取消：waiting / preparing → cancelled；generating / recovering → paused（停止等待，可继续查询）；混剪 tts / composing → cancelled
终态：completed / failed / cancelled；半终态（需人工动作）：save_failed / submission_unknown / paused
```

与众墅之家 `oral_tasks` 的对应关系（平移时按此改名，规则不变）：

| 众墅之家 status / submission_state | 本模块 phase |
|---|---|
| `QUEUED` / `LOCAL_PENDING` | `waiting`、`preparing` |
| `SUBMITTING` / `SUBMITTING` | `submitting` |
| `RUNNING`（`task_poll`） | `generating`、`recovering` |
| `ARCHIVING`（`task_archive`） | `downloading`、`verifying`（另加 `aligning`） |
| `SUCCEEDED` | `completed` |
| `ARCHIVE_FAILED` | `save_failed` |
| `SUBMISSION_UNCERTAIN` / `SUBMISSION_UNKNOWN`（含 2 小时轮询超时） | `submission_unknown` |
| `FAILED` | `failed` |

- **进度下限**（单调不回退，参照 AI-Studio `PHASE_FLOORS`）：waiting 0 / preparing 2 / submitting 5 / generating 8 / downloading 90 / verifying 94 / aligning 97 / completed 100；`generating` 内按「已耗时 / 预计生成秒数」在 8→89 之间推进；混剪 tts 2→15、aligning 15→20、`composing` 按 ffmpeg `out_time_us` 在 20→93 之间推进。
- **重启恢复（reconcile）**：见 FR-P6。
- **并发**：处于 `submitting / generating / recovering` 的任务数全局 ≤ `VIDEO_GEN_CONCURRENCY`（默认 3，对应飞影账号并发）；本地阶段（downloading / verifying / aligning / tts / composing）由 worker 并发（默认 2）控制，不占飞影名额；`waiting` 按 `queued_at` FIFO。同一 copy 同时只允许一个非终态任务（FR-A6）。
- **CAS 迁移**：所有阶段迁移 `UPDATE … WHERE id=? AND phase=?`（期望旧阶段），涉及飞影结果的再加 `AND remote_task_id=?`（同众墅之家 `WHERE status='RUNNING' AND vendor_task_id=?`）；失败即放弃本次推进（防 sweep 与 worker 双写）。**飞影调用一律在事务外**（`db.tx` 不可嵌套）。

### 3.2 版本与快照规则

- `version_no` 在 copy 内单调递增（取号 + 插入同一事务；并发撞 `UNIQUE(copy_id, version_no)` 时重试，参考文案工坊 `withDraftNoLock`）。
- 配置快照不可变：`config_snapshot` 冻结 `production-profile` 的完整返回（`versionId`、avatar、voice）、生成方式、提交参数（`vendor_title`、`aigc_flag`、`subtitle`）；人物库后续变化不改写快照。注意**声音参数存在飞影侧**，提交时飞影按其当前值合成，故提交前复核（FR-P2），复核通过即视为快照与实际一致。
- 口播文本快照不可变：`text_snapshot.segments` + `submit_text` + `text_hash`；与 `copy_version_id` 一一对应（同一版本切句规则不变时 hash 相同）。

### 3.4 时间轴对齐算法（V6 / FR-P5，默认方案 A）

1. 输入：`segments`（原文句列表）+ ASR 结果（句级 `beginTime / endTime` 与字 / 词级时间戳）。
2. 规范化两侧字符序列：去标点与空白、全角转半角、英文转小写；数字按「原文写法 ↔ 读法」建立等价表（如 `3.5%` ↔「百分之三点五」、`2026年` ↔「二零二六年」），等价片段作为一个对齐单元。
3. 用编辑距离（Needleman–Wunsch，替换 / 插入 / 删除代价 1，等价单元代价 0）对齐原文字符与 ASR 字符，得到原文每个字符 → ASR 字符时间的映射；未映射的原文字符按前后已映射字符线性插值。
4. 每句 `startMs` = 首字符时间，`endMs` = 末字符结束时间；相邻句重叠时取中点切开，保证单调无重叠；首句 ≥0，末句 ≤ 成片时长。
5. `align_score` = 匹配成功的原文字符数 / 原文字符总数；低于阈值或 ASR 失败 → 估算：按各句字数占比把 `[0, 成片时长]` 切分（风险段同样处理），`timeline_source=estimated`。
6. 字幕文本始终取原文句，ASR 的文字结果只用于对齐、不落入 `timeline`；ASR 原始结果存 `video_job_event.detail` 便于排障。

### 3.5 混剪匹配算法（一期关键词模式）

1. 输入：§3.4 得到的配音时间轴 `timeline`（句级起止毫秒）+ 启用的关键词组。
2. 平移 `KeywordModeProcessor.buildKeywordIndex / findKeywordsInText`：每句命中关键词按「最长关键词优先」取一个组。
3. 由组映射的素材包中按选择方式挑素材（同视频内去重），片段时长 = `min(句时长, 组 durationMax)` 且 ≥ `durationMin`，不足则顺延到下一句（不跨越风险段）。
4. **风险段（`kind=risk`）不覆盖素材**，保持底板，保证风险话术画面干净（剪辑模块再叠风险尾页）。
5. 产出 `MaterialReplacement[]`，交 `FFmpegCommandBuilder.buildOverlayCommand` 生成参数。

## 6. API 契约（REST，前缀 `/api`，沿用统一信封、分页与 `X-Operator`）

### 6.1 视频创作

```
-- 选项与预检
GET    /video/options                 模式、生成方式、飞影配置状态与剩余积分（脱敏）、计价规则、输出规格、上限、是否 MOCK
GET    /video/copies                  ?personaId&line&keyword&page   可用于视频创作的文案（已有通过版本）
GET    /video/copies/:copyId/context  文案卡 + 人物 + production-profile 摘要（未就绪时为 readiness checks）+ 分身列表（含不可选原因）
                                      + 混剪底板候选 + 已保存配置 + 版本列表
PUT    /video/copies/:copyId/config   保存配置（FR-C4）
POST   /video/precheck                {copyId, mode, avatarId?, backgroundAssetId?, voiceSource?, publicVoiceId?, mixcut?}
                                      → {estSeconds, estCredits, segments, checks[{key, level: hard|soft, pass, message, action?}]}
POST   /video/mixcut/preview          {copyId, mixcut} → {timelineEstimated[], matches[{index, keyword, itemId, startMs, endMs}]}
（声音试听直接调用人物库 POST /persona-voices/:id/preview，本模块不再提供试听接口）

-- 任务
POST   /video/jobs                    同 precheck 入参；头 Idempotency-Key → {jobId, versionNo, phase, replayed}
GET    /video/jobs                    ?copyId&personaId&phase&ids&page   （FR-X2）
GET    /video/jobs/:id                详情：阶段、进度、文案提示、下一步动作、快照摘要、飞影标题与任务号、时间轴（来源 / 分数）、替换点、预估积分、事件流水
GET    /video/jobs/:id/base           基础视频取用（FR-X1）
POST   /video/jobs/:id/refresh        立即查询一次飞影（generating / recovering）
POST   /video/jobs/:id/cancel         waiting/preparing（及混剪 tts/composing）→ cancelled；generating/recovering → paused
POST   /video/jobs/:id/resume         paused → recovering（继续查询）
POST   /video/jobs/:id/retry-download save_failed → downloading（只重下载，不重提交）
POST   /video/jobs/:id/query-original submission_unknown / failed（有飞影任务号）→ recovering（查询原任务）
POST   /video/jobs/:id/bind-remote    {remoteTaskId}  submission_unknown 且无任务号：补录在飞影后台按标题短引用找到的任务号 → recovering
POST   /video/jobs/:id/confirm-resubmit {confirm:true}  submission_unknown 且经人工确认未提交 → preparing（二次确认，submit_attempts+1）
POST   /video/jobs/:id/realign        completed 且 timeline_source=estimated（或人工要求）→ 重新对齐时间轴，不调用飞影
POST   /video/jobs/:id/archive        归档（不在列表显示，产物按留存策略清理）

-- 媒体
GET    /media/*                       本地兜底模式下的产物回放（Range、仅 .data/oss 内、签名 token 校验）
```

### 6.2 素材桩（素材库就绪后下线写接口）

GET                  /material-packs/:id/items

### 6.3 错误码（新增）

`VIDEO_MODE_NOT_ALLOWED`（素人线口播）、`VIDEO_PRECHECK_FAILED`（data 带 checks，含人物库 readiness 项）、`VIDEO_AVATAR_UNAVAILABLE`（所选分身不属于该人物或非 ready）、`VIDEO_PERSONA_CHANGED`（提交前复核不一致）、`VIDEO_TEXT_TOO_LONG`、`VIDEO_JOB_ACTIVE`、`VIDEO_JOB_LIMIT`、`VIDEO_NOT_READY`、`VIDEO_ENGINE_UNAVAILABLE`（飞影未配置且非 MOCK）、`VIDEO_VENDOR_REJECTED`（飞影业务码拒绝，data 带 `vendorCode`）、`VIDEO_SUBMISSION_UNKNOWN`、`VIDEO_POLL_TIMEOUT`、`VIDEO_SAVE_FAILED`、`VIDEO_RESULT_URL_BLOCKED`（结果地址未过防 SSRF 校验）、`VIDEO_STREAM_MISSING / VIDEO_DIMENSIONS_INVALID / VIDEO_DURATION_INVALID / MEDIA_EMPTY`（媒体校验）、`MATERIAL_PACK_EMPTY`；沿用 `COPY_NOT_APPROVED`、`INVALID_STATE`、`IDEMPOTENCY_CONFLICT`，以及人物库的 `PERSONA_NOT_READY`。
