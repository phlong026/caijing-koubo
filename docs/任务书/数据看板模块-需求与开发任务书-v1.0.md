## 1. 范围

### 1.1 一期做

- **数据层**：metric_snapshot / backfeed_suggestion / preference_profile 三表 + 迁移；CSV 导入（列映射模板 + 记录匹配 + 快照写入 + 爆款判定）。
- **回采框架**：MetricProvider 接口（collect(account, window) → 指标集）；csv 实现（即导入）、douyin-creator 占位（未启用报 `PROVIDER_UNAVAILABLE`）；T+1 / T+7 调度任务（BullMQ repeat，与 news 15min 同模式）：扫 finished_at 落入窗口且无快照的 publish_log → 依 provider 采集 → 写快照。
- **效果看板 Tab**：时间（近 7/30 天）/ 线 / 平台筛选 → 指标卡（发布作品 / 播放 / 互动）+ 播放趋势 + 内容表现列表（标题 / 平台 / 账号 / 人物 / 播放 / 互动 / 爆款 tag / T+1 vs T+7 对比）。
- **特征沉淀 Tab**：五维度统计表（高表现取值 / 爆款占比 / 状态待确认）+ 确认操作 → 写 preference_profile；口径说明（依据样本量与窗口）。
- **选题反馈 Tab**：反哺建议列表（依据 basis 展示）+ 加入选题库（创建 candidate topic）/ 忽略；对标优先级一键提升入口（爆款对标卡片）。
- **文案偏好默认注入**：copy 生成入口未显式传 instructions 时填充 active profile 的 basis_text（复用【补充要求】块既有链路，prompt 零改动）。

### 1.2 一期不做（边界）

- 创作者中心 Playwright 自动回采的真实实现（环境依赖与 PU9 相同，占位）
- 第三方数据服务接入（TikHub 类，二期评估）
- 封面图 CV 分析（文字密度 / 构图）、完播率曲线级数据
- 跨账号对比报表、ROI / 成本归因、导出 Excel
- 特征归因模型化（一期规则统计）
- 数据看板对工作台首页的嵌入（Q6）

## 3. 核心规则

### 3.1 数据流

```
publish_log(published) ──窗口到期──▶ 调度/手动 collect ──provider(csv|creator*)──▶ metric_snapshot
                                                                        │
                                              爆款判定（账号均值×3，样本≥5）──▶ is_hot
                                                                        │
                              ┌─────────────────────────────────────────┤
                              ▼                                         ▼
                    特征沉淀统计（五维度）                          选题建议（方向占比）
                              │ 确认                                    │ 人工确认
                              ▼                                         ▼
                  preference_profile(active)                    topic(candidate, data_backfeed)
                              │ 默认注入
                              ▼
                    copy 生成【补充要求】块（既有 prompt 链路）
```

### 3.2 匹配与覆盖规则（CSV）

1. 匹配顺序：external_video_id 精确 → (账号 + 标题完全一致 + 发布日期 ±1 天)；账号对齐走 `platform_account`（**display_name 必填**为 CSV 模板账号列口径，uid 登录确认后回填可能为空、不作主匹配键）。
2. 重导同窗口：覆盖（指标以最新为准），operation_log 留「重导覆盖」事件。
3. 无法匹配行：返回 `unmatched` 明细（少量不匹配 → 部分成功；**≥80% 不匹配 → 整单拒绝**并提示核对平台与账号），不写半截数据。

### 3.3 偏好注入优先级

用户显式 instructions > active preference_profile 的 basis_text > 无。注入经既有【补充要求】块（`prompt.ts:138-142`，消费 `instructions`，≤500 字——评审核实 `preferences` 入参全链路无消费，不依赖），注入文案固定模板化（如「近 7 天爆款特征：时长 30-60 秒、发布时段 18-24 点、选题方向偏基金科普——侧重但不强制」），**不得违反人设与合规前序规则**（prompt 块序已保证）。

## 4. 数据模型（3 张新表）

```
metric_snapshot: id, publish_log_id, platform, account_id,
  window(t1|t7), plays BIGINT, likes, comments, shares, collects, fans_gained,
  completion_rate(REAL,可空), is_hot(TINT 可空), account_avg_plays BIGINT(判定基准，可空),
  captured_at, source(csv|provider), created_at
  唯一: uk_msnip(publish_log_id, window)
  索引: idx_msnip_acct(account_id, captured_at)
  注：copy/persona/line 维度不冗余（与 DB2 单一事实源一致），overview 经 publish_log → plan → copy → persona JOIN 上卷（量级日产 ≤ 百条，无性能问题）

backfeed_suggestion: id, kind(topic|benchmark), basis(json 统计依据), payload(json 建议),
  status(pending|confirmed|dismissed), topic_id(可空), decided_by, decided_at, created_at
  索引: idx_bsug_status(status, created_at)

preference_profile: id, window_basis, profile(json 五维度结论), sample_count, basis_text(注入文案),
  status(active|archived), confirmed_by, created_at
```

迁移可回滚（三表均新表，DROP 即回滚）。数据留存 ≥2 年（A7，随库备份策略）。

## 7. 前端规格（改造 `DataBoard.vue`）

- **效果看板**：筛选行（近 7/30 天、线、平台）+ 指标卡（发布 / 播放 / 互动——互动 = 赞+评+转+藏）+ 播放按日趋势（沿用原型图表组件）+ 内容表现表（标题 / 平台 / 账号 / 人物 / T+1 播放 / T+7 播放 / 互动 / 爆款 tag；is_hot=null 显示「样本不足」灰 tag）；「最近回步」与 DB8 提示条；CSV 导入按钮（admin，弹窗含四平台模板下载）。
- **特征沉淀**：窗口切换（T+1 / T+7）+ 五维度表（维度 / 高表现取值 / 爆款占比 / 状态）+ 样本量与依据说明；「确认作为生成偏好」按钮（ops/admin）→ 二次确认（展示将注入的 basis_text 全文）。
- **选题反馈**：建议卡片（依据 basis 摘要）+ 加入选题库 / 忽略；对标优先级入口（匹配到对标账号的爆款卡片上「提升监控」按钮，显示当前间隔）。
- 空态：无快照数据时三 Tab 均显示引导「发布首批内容并导入 CSV 回采数据」。

## 10. 前置条件与风险

1. **平台指标口径差异**（最高风险）：各平台「播放」定义不同（如视频号为推荐播放）；一期以 CSV 模板列映射文档化口径，不跨平台直接对比绝对值（看板按平台筛选隔离）。
2. **CSV 人工成本**：日产内容多后手动导出繁琐——自动回采（创作者中心 / 第三方）二期必须跟上，一期在「最近回步」提示里持续暴露人工状态。
3. **小样本误判**：爆款阈值与特征占比在内容量 < 200 条时统计意义弱；DB3 样本下限 + AC-M3 样本门槛 + 特征页展示样本量，运营自行判断。
4. **偏好注入的生成漂移**：basis_text 措辞过强可能带偏文案风格——注入文案固定模板化（「侧重但不强制」），且确认时展示全文供人审。
5. **数据合规**：对标与自有账号数据留存 ≥2 年；CSV 含账号信息，导入日志脱敏展示。
6. ~~topics origin 字段可能不存在~~ → 评审核实已存在 `source` 列，风险消除。
