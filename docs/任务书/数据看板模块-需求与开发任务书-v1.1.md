**v1.0 之后的新增事实（写入开发约束）**：

1. 看板页「演示」标注文字已被移除（提交 `8797869`，10-28）——**页面视觉已"转正"但数据仍是 `mocks/data` 假数据**（`DataBoard.vue:240`）。上线前若 DB1~DB5 未完成，必须隐藏 `/analytics` 路由入口，不允许无标注的假数据上线（此为上线门禁，非本文档范围）。
2. `metrics` 模块现有 `GET /api-calls` + `GET /api-calls/summary`（FR-C4 成本记录，`modules/metrics/routes.ts` 9 行）——**保留不动**。新看板接口挂在新模块 `modules/analytics/`（避免与成本记录混域）；前端 `api/cost.ts` 已有的 summary 调用可在「效果看板」页头成本卡复用（可选，非 AC）。
3. 前端现状（`DataBoard.vue` 322 行）：三 Tab 骨架在、自绘 SVG 趋势曲线在（Catmull-Rom，`:252` 起）、无 loading/empty/error 三态、`contentPerf/trendData` 两个 mock 数组是全部数据源。**改造为保留骨架与图表绘制函数、替换数据层**（`stores/analytics.ts` 新建 + 删 `mocks/data` 引用）。
4. 多路 BullMQ 调度已有三个先例（news 15min / benchmark sweep 10s / video poll_sweep），T+1/T+7 repeat 照 `news/jobs.ts` 注册模式；**队列名新增 `metricCollect`**（`queue/index.ts QUEUE_NAMES`）。
5. multipart 上传先例：`personas/routes.ts` 的 FormData 直传与 `material-packs` 上传（含 settle 收口、大小上限、临时文件清理），CSV 导入直接复用该模式（上限 2MB，`CSV_TOO_LARGE`）。

## 3. 落地细化（文件级）

```
server/src/modules/analytics/          新模块（registerAnalyticsRoutes + 队列注册）
  routes.ts        §6 全部 10 个端点 + multipart（CSV）
  import.ts        papaparse 解析 + 四平台列映射模板 + 两级匹配 + upsert + 80% 拒绝
  snapshot.ts      快照 upsert（唯一键 publish_log_id+window）+ 爆款判定（90 天/5 条/均值×3）
  provider.ts      MetricProvider 接口 + csv/creator 占位（PROVIDER_UNAVAILABLE）
  schedule.ts      T+1/T+7 repeat + 手动 collect + pending 登记
  features.ts      五维度统计 + confirm 冻结 preference_profile + copy 默认注入
  suggestions.ts   建议生成（方向占比≥60%）+ confirm 创建 candidate topic + dismiss
server/src/db/schema.ts                +3 表（metric_snapshot / backfeed_suggestion / preference_profile）
server/src/modules/topics/repo.ts      TopicSource + 'data_backfeed'；assertTransition 规则一行
server/src/modules/copy/service.ts     生成入口 instructions 默认填充（一处，用户传入优先）
server/scripts/smoke-analytics.ts      冒烟（隔离环境，纳入 smoke:all）
frontend/src/stores/analytics.ts       新建（三 Tab 数据层 + 三态）
frontend/src/api/analytics.ts          新建（10 端点）
frontend/src/views/analytics/DataBoard.vue  接真：保骨架换数据，删 mocks/data 引用
frontend/src/mocks/data.ts             看板上线后删除（全站唯一引用是 DataBoard）
```

**开发顺序与依赖**：DB1（数据层+导入）→ DB2（调度）∥ DB3（统计+反哺）→ DB4（前端）→ DB5（联调+冒烟）。DB3 中「copy 默认注入」最后做并跑 `smoke:copy` 回归（AC-R1：无 active profile 时行为与现状完全一致）。

**copy 注入实现要点（AC-R1 零侵入验证）**：只在 `copy/service.ts` 生成入口（整稿与变体两处）判断 `instructions` 为空时填充 `preference_profile(active).basis_text`；填充动作写 operation_log（action=`copy.prefill_instructions`）便于回归排查；`smoke:copy` 既有 45 项不改动且必须全绿。
