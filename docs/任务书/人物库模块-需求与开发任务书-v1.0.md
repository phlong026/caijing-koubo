### 0.2 本模块决策（评审稿，默认方案待拍板）

| # | 决策 | 默认方案 | 理由 |
|---|---|---|---|
| L1 | 原地升级 persona 桩 | 在现有 `persona` 表上**增量加列**，不新建人物主表；`is_stub` 保留，存量 3 个示例人物保留 id、界面标「示例」、可归档 | A3：存量 copy/topic 已引用；一次迁移即切换数据源，接口不变 |
| L2 | 单层人物，不拆身份 / 人设 | 一期不引入众墅之家的 `PersonIdentity → CharacterPersona` 两层，**一个人物 = 一个 persona 行**；素材、分身、声音挂在人物下；人设与资产的历史由**人物版本快照**（L7）承担 | 众墅之家两层模型服务于「同一真人多套 AI 生图外观」，我们是真人实拍素材，两层只增加复杂度 |
| L3 | 口播分身 = 飞影训练型分身 | 上传人物口播源视频（素材）→ 本地质检与兼容转码 → 人工审核素材 → 克隆授权确认 → 提交飞影 `avatar/create_by_video` → 轮询 `avatar/task` → 拿到飞影 `avatar` 标识即 `ready`。照片制作分身（`create_by_image`）为企业会员能力，是否开放见 Q1 | A8；先审素材再提交，避免浪费飞影积分与合规风险 |
| L4 | 声音克隆走飞影 | 上传样本 → 转单声道 mp3（5–180 秒）→ 克隆授权确认 → 飞影 `voice/create`（`voice_type=8`）→ 轮询 `voice/task` 拿到 `voice` 标识与试听 `demo_url` → 归档试听 → 人工试听确认 → 可用 | A8；平移众墅之家已跑通的链路 |
| L5 | 授权是可用性的硬门槛 | 经理 / KOS 线：须有**已核验且未过期**的授权（肖像、声音分别核验）才可制作和使用对应分身 / 声音；授权失效 → 人物不可用（含文案用途，Q7）。素人线不强制授权 | 生物特征（肖像 / 声音）合规底线；对齐文案 FR-R3⑤ |
| L6 | 克隆须单次授权确认 | 每次分身 / 声音克隆须绑定「授权记录 + 确认文本版本 + 素材 SHA-256 + 用途（`AVATAR_CLONE` / `VOICE_CLONE`）」，任一不符即拒绝（平移众墅之家 `oral_consents`） | 防止用 A 的授权克隆 B、或替换素材 |
| L7 | 人物版本快照 | 「保存定位」内容 hash 变化、或默认分身 / 声音变化、或声音参数变化时，生成**不可变**人物版本（`persona_version`）；文案生成、视频任务绑定版本 id | 平移众墅之家 `CharacterVersion.persona_snapshot_json`；对齐「全链路版本」 |
| L8 | 先审后用 | 照片 / 背景 / 空镜 / 分身素材：自动质检后人工审核通过才可用；分身素材**审核通过才能提交克隆**；克隆声音须**人工试听确认**才可用（平移 `confirm_voice_clone`） | 效果图「声音待确认」；省积分、控合规 |
| L9 | 不确定态必须人工核对 | 飞影创建请求发出但未拿到 `task_id`（网络中断 / 超时，众墅之家 `HiflySubmissionUncertain`）→ `uncertain`；轮询超过 2 小时仍非终态 → `uncertain`。**禁止自动重提**，须「核对状态」：按提交时写入标题的短引用到飞影 `avatar/list` / `voice/list` 查找，查到则补写标识，确认不存在才允许重新提交 | 效果图「状态待核对，请先核对状态，勿重复创建」；避免重复扣积分、重复分身 |
| L10 | 只归档 / 软删 | 人物只可归档；分身、声音、素材为软删，记录与审计保留 ≥2 年。**飞影没有删除接口**，软删只在本地隐藏，飞影侧资源保留（众墅之家同样处理） | PRD 8.4；历史文案 / 视频需可追溯 |
| L11 | 账号绑定先存标识 | 平台账号表归发布管理（M4）。一期绑定只存「平台 + 账号标识 + 显示名」，M4 落地后迁移为外键；规则：经理**一对一**，KOS **可共享**（默认上限 5） | 不阻塞开工，又把「可用范围」规则先立住 |
| L12 | 私有存储 | 素材、样本、授权材料一律私有：OSS 私有桶或本地 `.data` 兜底；前端只经后端短时签名 URL / 流式接口读取；读取授权材料与样本原件记审计 | 肖像、声音、身份证明属敏感个人信息 |
| L13 | 素材交给飞影的方式 | 优先「飞影自取」：OSS 签发 24 小时签名 URL 传 `video_url / audio_url`；无公网可达 URL（本地兜底存储）时回落「自上传」：`tool/create_upload_url` + PUT 原始字节，只对超时重试 2 次、每次换新凭证（平移 `_vendor_fetchable_url` / `_transfer_material_to_vendor`） | 众墅之家 2026-10-11 事故：38.6MB 4K 素材自上传 60 秒超时；自取不占服务器出口 |
| L14 | 积分与套餐限制可见 | 飞影按积分计费：`GET /personas/options` 带账户剩余积分（`account/credit`，缓存 5 分钟）；飞影业务码映射为可读错误（1002 积分不足、1009 声音数量达上限、1011 素材未过合规校验、1005/1006 套餐不支持、1001/1015 并发或提交数上限、2003 未配置）；每次调用写 `api_call_log(provider=hifly)` | 运营能在失败前看到余额，失败后知道原因 |
| L15 | 背景随分身 | 飞影分身的背景由源视频决定，**不支持换背景**。每个分身登记「背景名」（如「白色简洁」），视频创作屏的「背景」= 选分身。人物库的背景图 / 背景视频 / 空镜作为剪辑、封面、混剪素材登记，不参与飞影生成 | 与视频创作屏「背景：小林 · 白色简洁 · 已绑定人物资源」一致；不承诺做不到的抠像 |

### 2.3 形象资产（FR-A）

通用规则：multipart 单文件；**扩展名 + 魔数 + 结构**三重校验（R31、R27）；私有存储（L12）；同一人物同类资产按 SHA-256 去重；异步处理（队列 `persona-asset-process`）→ 自动质检 → `pending_review` → 人工「通过 / 驳回（原因必填，可选 issue code）」→ 通过才可用（L8）。删除为软删。

| FR | 需求 | 细则 |
|---|---|---|
| FR-A1 | 形象照片 | jpg / png / webp，≤10MB；最短边 ≥720 px（R26）；读 EXIF 方向并规范化；生成 320px 缩略图。质检：尺寸、清晰度（仅提示）、结构完整。用途：封面、发布头像候选；Q1 开放时可作为照片分身的来源。每人 ≤50 张。可「设为封面」 |
| FR-A2 | 分身素材 | 仅经理 / KOS 线（素人 400 `PERSONA_LINE_NOT_ALLOWED`）。mp4 / mov，≤200MB；时长 10 秒–10 分钟（以飞影要求为准，PL4 探活时核对）；处理：ffprobe 元数据 → **生成兼容版本**（H.264 mp4，R20/R21）→ 抽帧封面 → 质检。硬性质检不过即 `failed`：可解码、有视频流、时长区间、短边 ≥720；软性提示：非 9:16、帧率 <24、码率过低。登记「背景名」（≤20 字，L15）。审核通过后才可发起分身制作（FR-C1）。每人 ≤10 个 |
| FR-A3 | 背景与空镜 | 背景图（jpg/png/webp ≤10MB）、背景视频（mp4/mov ≤200MB，≤60 秒）、空镜视频（同上）。可打标签（≤10 个，供剪辑 / 混剪关键词匹配）。不参与飞影生成（L15）。三类各 ≤30 个 |
| FR-A4 | 预览 | 缩略图与原图、视频封面与播放均经 `GET /persona-assets/:id/file`（支持 Range）；不暴露存储真实路径 / 长期公网 URL |
| FR-A5 | 计数 | 卡片「照片」计数只统计已通过审核的照片；「分身」计数 = `ready` 的飞影分身数；详情 Tab 列出全部状态，失败显示原因并可删除重传 |

### 2.4 口播分身（FR-C，飞影）

| FR | 需求 | 细则 |
|---|---|---|
| FR-C1 | 发起制作 | 在已审核通过的分身素材上点「制作分身」：① 选择该人物**已核验、未过期、范围含「肖像」**的授权（无则 `AUTHORIZATION_REQUIRED`）并勾选确认文本 → 生成 consent（`AVATAR_CLONE`，绑定素材兼容版本的 SHA-256，R12）② 填分身名称（≤60 字，默认「人物名 · 背景名」）→ `POST /personas/:id/avatars`（头 `Idempotency-Key`）。幂等（R13）：同键同参返回原记录；同键异参 409 `IDEMPOTENCY_CONFLICT`。同一素材已有 `ready` 或进行中分身时提示「该素材已制作分身」，需二次确认才再提交 |
| FR-C2 | 制作执行 | 入队 `persona-clone`：飞影标题 = 名称截断 + 短引用（R11，≤20 字）→ 素材交付（L13：签名 URL 自取，否则自上传）→ `avatar/create_by_video`（`aigc_flag` 默认 1，Q11）→ 落 `vendor_task_id` 转 `running` → 轮询 `avatar/task`（15 秒起，指数退避至 2 分钟）→ DONE 且有 `avatar` 标识 → `ready`；FAILED → `failed`（原因经业务码映射，如「该素材未通过数字人服务合规校验」）；DONE 但缺标识 → 继续等待（R15） |
| FR-C3 | 不确定态 | 提交未拿到 `task_id`（R2）或轮询超过 2 小时（R9）→ `uncertain`：卡片显示「状态待核对，请先核对状态，勿重复创建」，只提供「核对状态」：调 `avatar/list`（`kind=2`，分页扫描）按短引用匹配标题——查到：补写 `vendor_avatar_id` 直接 `ready`；列表无且飞影任务号存在：再查一次 `avatar/task`；确认不存在：转 `failed` 并允许重新制作（新 Idempotency-Key 新记录）。核对结果与依据写 `operation_log` |
| FR-C4 | 使用与默认 | `ready` 分身可设为默认分身；默认分身须肖像授权有效。分身卡显示：封面帧、名称、背景名、素材分辨率 · 时长、制作状态、默认标 |
| FR-C5 | 重命名与删除 | 重命名只改本地（R18）。软删（R19）：制作中 / 不确定态不可删；默认分身须先换默认；被进行中视频任务引用不可删（M3 接入后生效）。飞影侧分身保留（L10） |
| FR-C6 | 照片分身（Q1） | Q1 开放时：在已审核照片上发起，走 `avatar/create_by_image`；飞影返回 1005/1006 时提示「当前飞影套餐不支持照片制作分身」 |

## 3. 状态、规则与算法

### 3.1 存储状态

```
persona        enabled(0/1，手动开关) + archived_at(可空)
authorization  pending ──核验通过──→ verified ──撤销──→ revoked
                  └──驳回──→ rejected            （verified 且已到期 → 读时派生 expired）
asset          uploaded → processing → pending_review ──通过──→ approved
                               └──→ failed            └──驳回──→ rejected        （任一态可软删）

avatar / voice（飞影克隆，平移 oral_avatars / oral_voices）
  pending ──入队──→ submitting ──拿到 task_id──→ running ──DONE 且有标识──→ ready
                       │                            ├──FAILED──→ failed
                       │                            └──超过 2 小时──→ uncertain
                       ├──业务码错误──→ failed
                       └──无业务码的异常 / 超时──→ uncertain ──核对──→ ready | running | failed
  voice：ready ──人工试听确认──→ ready + confirmed
```

### 3.2 人物有效状态（读时派生，平移 R23，不入库）

按顺序取第一个命中：

| 有效状态 | 条件 | 界面标签 | usable |
|---|---|---|---|
| `archived` | `archived_at` 非空 | 已归档 | 否 |
| `disabled` | `enabled = 0` | 已停用 | 否 |
| `auth_revoked` | 经理 / KOS 线，覆盖「肖像」或「声音」的授权已撤销，且无其他有效授权 | 授权已撤销 | 否 |
| `auth_expired` | 经理 / KOS 线，有过有效授权但当前均已过期 | 授权已过期 | 否 |
| `auth_pending` | 经理 / KOS 线，没有任何 `verified` 未过期授权 | 授权待核验 | 否 |
| `active` | 以上都不命中 | （附加标签） | 是 |

附加标签（不影响 `usable`，影响 readiness）：「声音待确认」「分身制作中」「状态待核对」（存在 `uncertain` 分身或声音）、「授权将到期」（30 天内）、「待完善」（经理 / KOS 缺 ready 默认分身或已确认默认声音）、「已配置」（readiness(avatar_video) 全过；素人线为 readiness(copy) 全过）。

**资产可用**：照片 / 背景 / 空镜 = `approved` 且未软删；分身 = `ready` 且未软删且肖像授权有效；声音 = `ready` 且 `confirmed=1` 且未软删且声音授权有效（共享人物另需「允许共享」）。

### 3.3 线规则

| 能力 | 经理 IP（manager） | 员工 KOS（kos） | 素人（persona） |
|---|---|---|---|
| 形象照片 / 背景 / 空镜 | ✓ | ✓ | ✓ |
| 分身素材与飞影分身 | ✓ | ✓ | ✗（400 `PERSONA_LINE_NOT_ALLOWED`） |
| 飞影声音克隆 | ✓ | ✓ | ✗（Q3） |
| 授权要求 | 必须 | 必须 | 不强制（可上传留档） |
| 绑定方式 | 一对一（固定） | 共享（默认）/ 一对一 | 一对一 |
| 账号上限 | 1 | 共享 5 / 一对一 1 | 1 |

### 3.4 人物版本快照（L7）

- 触发：① 保存定位且规范化 hash 变化；② 默认分身 / 默认声音变化；③ 声音参数变化。
- 内容：基本信息、完整 `ipProfile`、默认分身（本地 id、`vendor_avatar_id`、背景名、素材 SHA-256）、默认声音（本地 id、`vendor_voice_id`、语种、参数）、授权摘要（有效授权 id 与到期日）。
- `snapshot_hash` = 规范化 JSON 的 SHA-256；与最新版本相同则不新建；`UNIQUE(persona_id, version_no)` + 重试兜底。版本不可改、不可删。

### 3.5 关键校验规则

- 名称唯一：`active_name_key` = 规范化名称；归档时置 NULL；`UNIQUE(active_name_key)`（MySQL 允许多个 NULL）。
- 资产去重：唯一键建在 `(persona_id, kind, sha256_key)`，软删时 `sha256_key` 置 NULL。
- 克隆幂等：`UNIQUE(idempotency_key)`；`request_hash` = 规范化请求 JSON 的 SHA-256（R13/R14）。
- 飞影标题：`{名称前缀}-{短引用}`，总长 ≤20 字；短引用 = 记录 id 派生的 6 位 base32，库内唯一，用于核对（R11）。
- 并发写：人物 `rev` 乐观锁；克隆状态推进全部 CAS（`WHERE status = ? AND vendor_task_id = ?`），影响行数 ≠1 时回查判定幂等或冲突；**飞影调用一律在事务外**，遵守 `db.tx` 不可嵌套。
- 提交防重：`submitting` 状态由队列单消费者持有（`dedupOpts(recordId)`）；进程重启后发现停留在 `submitting` 的记录直接转 `uncertain`，不重提（R9）。

## 7. 非功能需求

- **隐私与合规**：肖像、声音样本、授权材料按敏感个人信息处理：私有存储、无长期公网直链；交给飞影自取的签名 URL 有效期 24 小时（L13）、仅用于提交，不落日志（日志与 `api_call_log` 对签名参数脱敏）；敏感原件访问留痕；被驳回 / 软删素材的存储对象 30 天后清理（记录保留）。飞影侧提交默认带 AIGC 标识（Q11）。
- **幂等**：克隆（Idempotency-Key + request_hash）、素材（SHA-256 去重）、保存定位（hash 不变不升版本）、确认 / 审核（CAS + 重复幂等）。
- **防重复扣费**：创建类飞影调用每条记录**最多发出一次**；任何不确定都进入 `uncertain` 走人工核对；重启不重提。
- **并发**：人物 `rev` 乐观锁；状态推进 CAS；飞影调用在事务外；版本号唯一键兜底。
- **安全**：上传扩展名 + 魔数 + 结构校验；ffprobe / ffmpeg 只处理本地文件并设超时；存储 key = `persona/{personaId}/{kind}/{id}.{ext}`；飞影请求只发往配置的官方域名，下载试听仅接受飞影返回的 https 地址并设大小上限。
- **性能**：`GET /personas` 500 人 P95 < 300ms；详情 P95 < 300ms；图片处理 < 10 秒；200MB 分身素材兼容转码 < 3 分钟（本机基准，记录实测）；飞影制作耗时以 PL4 探活实测为准并在 options 中给出预计时长。
- **可观测**：三个队列失败计数进 `/api/health`；克隆状态、飞影任务号、失败原因（含业务码）可查；每次飞影调用写 `api_call_log(provider=hifly, ref_type=persona_avatar|persona_voice)`。
- **审计**：新建、编辑、保存定位、启停、归档、素材上传 / 审核 / 删除、授权上传 / 核验 / 撤销、consent、分身 / 声音的发起 / 核对 / 确认 / 参数 / 设默认 / 删除、绑定变更全部落 `operation_log`（留存 ≥2 年）。
- **降级**：无 OSS → 本地兜底 + 自上传给飞影；无飞影密钥且 `MOCK_FALLBACK=true` → mock 客户端（确定性标识、ffmpeg 生成提示音试听，可注入 uncertain / failed）；无 Redis → 内存队列。

### 14.4 与本文不一致处（需评审知悉）

1. **授权按「人物是否有任一有效授权覆盖该范围」判定，而非绑定创建时那份授权**。原因：授权续期只能新建记录，若分身 / 声音永久绑定旧授权，续期后永远不可用（§9.10 场景 3 要求「补授权后全部恢复」）。创建时仍要求所选授权有效，所选授权 id 与 consent 照常留痕。
2. **示例人物授权**由迁移 `006_stub_authorizations` 种入（非「测试夹具」）。
3. **「已配置」附加标签**仅对「可用且已设默认分身 + 默认声音」的人物才计算 readiness，避免列表逐人多查。
4. **分身 / 声音失败原因**：已知业务码一律用本地中文映射，厂商原话保留在 `details.vendorMessage`。
5. **`GET /personas/:id/avatars` 之类的接口均已按 §5.1 实现**（50 个接口逐条核对无缺）。
6. **飞影客户端协议对齐（2026-10-28）**：R1 平移时引入 6 处协议漂移，已逐项对照官方文档与众墅之家生产实现修复——查询类接口（task / list / credit）为 GET + query 参数（原误用 POST + body）；任务标识响应字段为 `avatar` / `voice`（原只取 `avatar_id` / `voice_id`，DONE 也拿不到标识）；余额字段 `left`；list 分页参数 `page` / `size` 且行数组在 `data.data`；`voice/edit` 参数 `voice` / `rate`（字符串格式）；`video|audio/create_by_tts` 参数 `avatar` / `voice` 且无语速类参数（语速 / 音量 / 音调经 `voice/edit` 在声音侧生效，提交时不再传）。契约测试响应样例同步重写为官方真实协议并补 GET / query 断言（24 项）。
