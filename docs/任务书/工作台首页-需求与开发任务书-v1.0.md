>   - 发布：`listPlans(f)` + `nextActionOf(plan)`（`publish/plans.ts:90,131`），`plan.status ∈ draft|scheduled|executing|completed|partial|failed|cancelled`，`plan.reviewState ∈ none|needs_review|confirmed`；
>   - 数据回采：`countDueLogs(window)` 直接给出「到期未采」条数（`analytics/snapshot.ts:165`），`lastCapturedAt(window)` 给最近导入时间；
>   - 账号登录态：`platform_account.login_status ∈ pending_login|active|expired|failed|disabled`（`publish/types.ts:14`），`listAccounts({loginStatus})` 可直接筛；
>   - 文案审核结果：`copy.status ∈ draft|in_review|approved|rejected|archived`（`copy/constants.ts:10`），`copy.reject_reason` + `review_submission.external_status` 可区分「校对台意见」与「本地驳回」。

> - **既有约定**：任务中心是「下一步动作」的唯一出口（`ACTION_LABELS` / §3.4 路由映射），工作台只做「看 + 跳」，不复制动作推导、不提供写操作；时间展示统一按 `Asia/Shanghai` 渲染（`TaskCenter.vue:403` 已有先例）。
> - **口径陷阱（评审核实）**：`publish/accounts.ts:256 publishedTodayOf()` 用的是 **UTC 日界** 且只统计 `source='auto'` 的发布，与「北京时间今日」不一致。工作台的「今日」计数必须新写，**不得复用该函数**（见 §3.4 / AC-WB6）。

## 1. 范围

### 1.1 一期做

- **后端聚合模块** `server/src/modules/workbench/`：`summary.ts`（聚合与口径）+ `routes.ts`（1 个只读端点）+ `types.ts`；注册进 `routes.ts`。
- **四张卡**：待处理任务 / 审核退回待改稿 / 成片待发布 / 数据待回采，各带按线或按平台的明细拆分与跳转目标。
- **今日概览**：今日新建文案数（按线）、今日已发布数（按线）、今日新增任务数（PageHead 副标用）。
- **三条生产线卡片**：每线今日新建 / 今日已发布 / 当前待处理 + 阶段分布（文案 / 视频 / 剪辑 / 发布哪个阶段积压最多）。
- **待处理列表**：Top 5，含动作文案与跳转。
- **告警摘要条**：四类告警计数与跳转。
- **前端**：`api/workbench.ts`、`stores/workbench.ts`、`Workbench.vue` 接真 + 三态 + 降级提示；快捷入口保持静态。
- **测试**：`server/scripts/smoke-workbench.ts`（造数覆盖四卡 / 三线 / 告警 / 降级 / 角色），纳入 `smoke:all`。

### 1.2 一期不做（边界）

- 自定义卡片编排 / 拖拽 / 个人看板配置（二期，需要偏好存储）
- 页内审批、发布、重试、改稿等**写操作**（一律跳各模块，见 A5）
- 趋势图与多日对比（属数据看板效果看板 Tab，A1）
- 站内通知中心、邮件 / 企业微信推送（告警只做页面提示）
- 「日均产能 / 目标达成率」（无目标值与历史基线，待运营定 SLA 后另立）
- 移动端专用布局（沿用后台响应式断点）

## 3. 聚合规则

### 3.1 卡片口径

| 卡片 | 定义 | 明细拆分 | 数据来源 |
|---|---|---|---|
| 待处理任务 | 未归档文案中 `needAttention === true` 的数量（= 任务中心 `counts.todo`） | 按线 `{manager, kos, persona}` | `task-center` 聚合（复用 `listCandidateCopies` + `aggregate`，不重复实现判定） |
| 审核退回待改稿 | `copy.status = 'rejected'` 且未归档 | `external`：`reject_reason` 以「校对台」开头（平台意见） / 本地驳回 | `copy` 表 + `review_submission.external_status` |
| 成片待发布 | `publish_plan` 未删除且 `status ∈ (draft, scheduled)`（**不卡 `reviewState`**：`needs_review` 的草稿同样卡在「还没发出去」，漏掉会让复审单无处可寻） | 按平台（`publish_log` 计划内平台）；hint 追加「其中待复审 N 条」 | `publish_plan` + `publish_log` |
| 数据待回采 | `countDueLogs('t1')` + `countDueLogs('t7')`（已发布超窗口延迟且无快照） | `t1` / `t7` 分组 | `analytics/snapshot.countDueLogs` |

> 口径说明：「待发布」不含 `executing`（正在发，不需要人动手）与 `partial/failed`（属告警），避免同一件事在两张卡上重复计数；但**包含 `reviewState='needs_review'`**——那是「等我们确认才能发」的单，同样需要人处理，只是 hint 里单独标注条数。

### 3.2 「今日」口径

- 日界：北京时间 00:00:00（`Asia/Shanghai`），实现取 `Intl` 或 `+08:00` 偏移计算，**不写 UTC 日界**。
- 今日新建文案：`copy.created_at ∈ [今日00:00, 明日00:00)` 且 `archived_at IS NULL`，按 `line` 分组。
- 今日已发布：`publish_log.status='published'` 且 `finished_at ∈ 今日区间`，按 `publish_log` JOIN `platform_account.line` 分组；**不区分 `source`**（人工补发也算产能）。
- 今日新增任务：同「今日新建文案」（任务 = 文案档案，任务中心即按 copy 建档）。

### 3.3 三线阶段分布

- 阶段取值固定为任务中心的 `stage.key`：`topic | copy | base_video | edit | publish`（`task-center/types.ts:6`）。
- 每线统计「当前未完成任务在各阶段的条数」，取前 3 个非零阶段展示（文案 / 视频 / 剪辑 / 发布），用于回答「这条线卡在哪」。
- 已归档（`archived_at` 非空）与 `cancelled` 不计入。

### 3.4 禁止复用项

- `publish/accounts.ts publishedTodayOf()`：UTC 日界 + 仅 `source='auto'`，与 §3.2 冲突（评审核实）。工作台自行实现 `publishedTodayByLine()`。
- 前端本地计算任何卡片数值：数值一律服务端给，前端只格式化（避免两端口径分叉）。

### 3.5 排序与截断

- 待处理列表：`updatedAt` 倒序取 5 条；同时间按 `copyId` 稳定排序。
- 告警：严重度 `error`（发布失败 / 视频失败）> `warn`（账号失效）> `info`（校对台拒收）；同级按数量倒序。

### 3.6 告警阈值与降噪

| 告警 | 触发条件 | 级别 | 跳转 |
|---|---|---|---|
| 发布失败 | `publish_log.status ∈ (failed, failed_final)` 且 `updated_at` 近 7 天 | error | `/publish`（记录在「发布记录」tab，一期不带筛选直达） |
| 视频生成失败 | `video_job.phase ∈ (failed, save_failed, submission_unknown)` 且近 7 天 | error | `/tasks?status=attention`（TaskCenter 支持 `?status=`） |
| 账号登录态失效 | `platform_account.login_status ∈ (expired, failed)` 且 `enabled=1`、未删除 | warn | `/publish`（账号状态目前只在发布页内可见，**无独立账号管理页** → 见 §12 缺口） |
| 校对台拒收 | `review_submission.external_status='resubmit_refused'` 且近 7 天 | info | `/copy` |

> 降噪：同一条发布记录多次重试只计最后一条（按 `plan_id + platform` 取最新 attempt）；账号类按账号计，不按失败次数计。

### 3.7 降级与超时

- 每个来源独立 `try/catch`：失败记 `warn` 日志 + `degraded.push(source)`，对应字段置 `null`。
- 聚合总耗时目标 < 300ms（当前量级：文案档案 < 1k、发布记录 < 1w）；单源超 1s 视为失败并降级（`Promise.race` 超时），避免首页被慢查询拖住。

## 4. 数据模型

**不新建表。** 依赖既有表与字段：

| 表 | 用到的字段 | 用途 |
|---|---|---|
| `copy` | `id, title, line, status, created_at, updated_at, archived_at, review_submission_id` | 待处理 / 待改稿 / 今日新建 |
| `review_submission` | `external_status, status` | 区分校对台意见与本地驳回 |
| `publish_plan` | `id, copy_id, status, review_state, deleted_at` | 待发布 |

## 7. 前端规格（对照现有 `Workbench.vue` 版式，换数据层）

- **保留**：PageHead（标题 + 日期副标）、四卡网格、三线三列、左「待处理」右「快捷入口」双栏、`mw-card` / `mw-tag` / `mw-link` 视觉语言。
- **改造**：
  - 四卡接 `cards.*`：名称改为 待处理任务 / 审核退回待改稿 / 成片待发布 / 数据待回采（替换现有「今日新增任务 / 待人工审核」两张）；hint 用 `byLine` / `byPlatform` / `t1·t7` 拼装。
  - PageHead 副标接 `today`：`2026年10月28日 星期三 · 今日新增 6 条 · 三条生产线并行`。
  - 三线卡片：`scopeText` 来自静态配置（平台范围与日更节奏属业务约定，不入库）；三个数字接 `todayNew / todayPublished / attention`；阶段分布改条形（按 count 归一，最多 3 段）；底部「进入该线 →」跳 `lines[].to`。
  - 待处理：接 `todos`（5 条），动作标签用 `actionLabel`，整行跳 `routeOfAction(action, copyId, refId)`；空态文案「当前没有待处理的任务」。
  - 告警条：卡片区上方一行 chip，无告警则整行不渲染。
  - 快捷入口：保持 `quicks` 静态常量不变（4 个）。
- **三态**：
  - loading：四卡 + 三线用骨架块（不用全屏 spinner，避免首屏跳动）。
  - error（整页失败，`WORKBENCH_UNAVAILABLE` 或网络错误）：居中提示 + 重试。
  - empty（`today.newCopies=0 && cards.*.value=0 && todos 为空`）：卡片保留 0，待处理区显示引导「当前没有进行中的任务 · 去爆款选题创建第一条内容」（同一文案覆盖「从未使用」与「暂时无事」两种情形，避免系统已用但当天清空时出现「开始第一条内容」的误导）。
- **降级**：`degraded` 非空 → 对应卡值显「—」+ 卡右上 `mw-tag-gray`「数据源异常」。
- **轮询**：60s，`document.hidden` 跳过；`onBeforeUnmount` 清理定时器；手动刷新按钮 `loading` 绑定请求中状态。
- **时间渲染**：`Asia/Shanghai`，格式 `MM.DD HH:mm`（与看板 `fmtTime` 一致）。
