## 2. 联调中发现并修复的缺陷

这些问题在后端 smoke 全绿时都没有暴露：smoke 直接调接口、手动调用 sweep，不经过页面。

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | `video-poll-sweep` 队列只排了周期任务、**没有注册消费者** | 生产环境视频任务永远停在「排队中」，飞影生成中也不会被轮询——视频创作主功能不可用（smoke 手动调 `runVideoSweep` 掩盖） | 调度时一并注册 worker（`video/worker.ts`） |
| 2 | `video-cut-sweep` 同样没有消费者 | 剪辑「取消渲染」永远停在 cancelling；渲染超时、queued 滞留无人兜底 | 同上（`cut/worker.ts`） |
| 3 | `GET /material-keyword-groups` 按不存在的 `created_at` 排序，恒 500 | 视频创作页加载即报错；页面用 `Promise.all` 同时取素材包，**素材混剪选不到任何素材包** | 改按 `sort, id` 排序；smoke-video 补列表断言 |
| 4 | 生成完成后预览区仍是「配置完成点击下方生成」 | 停在页面上等完成看不到成片，须再去版本列表点一次（违背 FR-A8） | 跟踪中的任务转 completed 时自动选中并播放 |
| 5 | 发布页「待安排」标题与预填标题用的是飞影侧 `vendorTitle`（截断 + 短码） | **每个发布计划都被判为「标题实质修改」需审核确认**，无法直接发布 | `GET /video/jobs` 返回 `copyTitle`（视频所用文案版本标题）；选中时预填当前过审标题 |
| 6 | 计划需审核确认时「创建并立即发布」仍调 execute-now | 409 报错弹窗 | 需审核时只提示等待确认，不再立即发布 |
| 7 | 切换到「发布记录 / 发布计划」Tab 不拉数据 | 刚发布完切过去显示「暂无发布记录」，最多等 20 秒轮询 | 切 Tab 即加载该 Tab |

## 3. 如何运行

```bash
cd server && npm ci
cd ../frontend && npm ci          # 含 playwright 1.56.1（devDependency）
npx playwright install chromium   # 本机首次；CI 用 --with-deps

npm run e2e                       # 自动拉起隔离后端（:9897）与 Vite（:5173），跑 people + main，结束清理
npm run e2e -- --suites=main      # 只跑主链路
npm run e2e -- --real --oss       # 后端改用真实 MySQL + Redis（DB_* / REDIS_*）与 OSS 仿真
E2E_ARTIFACTS=e2e-artifacts npm run e2e   # 截图落到 frontend/e2e-artifacts（CI 失败时上传）
```

手工联调可单独起后端：`cd server && node --import tsx scripts/serve-e2e.ts`。它和 `test-integration --serve` 的区别是补齐了发布模块与审核桩续推的装配，并把视频 / 剪辑 / 发布 / 飞影轮询压到秒级。

CI：`.github/workflows/ci.yml` 新增 `e2e` job，每次 push / PR 运行。
