## 一、结论摘要

**工作台首页是「登录后默认落地页 + 100% 硬编码假数据 + 零请求 + 零测试覆盖」，且演示标注已被移除。** 它比数据看板整改前更危险 —— 看板至少还有入口可摘，首页是所有人登录后看到的第一屏。

三条核心结论：

1. **P0 误导风险已成立**：`8797869`（「移除界面上全部演示/示例标注文字」）删掉了 `Workbench.vue` 的「演示环境 · 平台回采与发布授权能力待验证」横幅与「原型预览 · 演示数据」角标（diff 保留在报告中），但 `metrics` / `lines` / `todos` 依然是常量。用户现在看到的「今日新增 6 · 待人工审核 2 · 已产出 10 条」没有任何来源。
2. **v1.0 任务书方向正确、口径基本可落地，但有 4 处与代码事实冲突已在同轮修正**（详见 §3.2）：初稿写了「卡片 `to` 带 `?status=`」与「服务端给 `to`」—— 核实后 `CopyStudio` 只认 `?id=`/`?ids=`、`PublishManage` 只认 `?copyId=` 且内部 tab 不读 query；而 `routeOfAction` 含前端 feature flag 分支，服务端不可能产出正确目标。已改为「卡片固定入口 + 待办走前端共享 `routeOfAction`」，并新增 WB11/Q9/Q10。第 4 处是「待发布」卡把 `needs_review` 的草稿计划漏掉了。
3. **任务书覆盖了现状的全部缺陷，无一遗漏**；剩余 3 个缺口是「环境缺口」而非文档缺口（无账号管理页、无产能目标值、告警无静音），已在 §12 明确标注「不在本期修」。

| v1.0 任务 | 现状 | 差距 |
|---|---|---|
| WB0 契约冻结 | — | 待评审拍板（Q1~Q10） |
| WB1 后端聚合 | 无 `modules/workbench/`；`server/src/routes.ts` 无注册 | 全新建（5 个来源函数均已存在，只读编排） |
| WB2 前端接真 | `Workbench.vue` 零 API、零 lifecycle（`grep onMounted\|fetch` 无命中） | 换数据层 + 抽 `taskRoutes.ts` + 补三态 |
| WB3 联调冒烟 | 无 `smoke:workbench`；`e2e/` 三个脚本均不访问 `/workbench` | 新建 |

**可复用资产比预期好**：页面版式（四卡网格 / 三线三列 / 左下待办右快捷入口）已按效果图实现且视觉可用，`mw-card`/`mw-tag`/`mw-link` 语言统一；后端 5 个来源函数签名齐备（`countDueLogs` / `listPlans` / `nextActionOf` / `listAccounts` / `listTasks` 的 `counts{todo}`）。WB1+WB2 实质是「编排 + 换数据」，不是重写。

**建议补强的 4 个点**（其中第 3 条已在同轮并入正文；其余 3 条建议写进 v1.1）：

1. **告警没有「已确认 / 静音」机制**：`account_expired` 这类状态会长期驻留，首页天天挂同一条会脱敏（告警疲劳）。建议 v1.1 明确「一期不做静音，但文案区分为『持续 N 天』」，或在 §1.2 明写「不做告警确认」以免评审后被追问。
2. **`scope=mine` 缺少前端入口说明**：WB 决策支持 `scope=mine`，但 §7 前端规格没写切换控件位置。建议明确「一期只读 query，不暴露 UI 开关」，否则验收时无法判定。
3. **空态文案歧义**（已在 v1.0 同轮处理）：判定条件「四卡全 0 + 今日 0 + 待办空」在「系统已用但当天清空」时也会命中，原文案「去爆款选题开始第一条内容」会误导老用户。已改为中性文案「当前没有进行中的任务 · 去爆款选题创建第一条内容」，不动判定条件（改条件需给 API 增 `copyTotal`，不值当）。
4. **聚合端点无缓存**：60s 轮询 × 并发人数会重复跑全量投影。建议 v1.1 增一句「同一实例内 10s 结果缓存（`generatedAt` 透出），或至少评估后再定」。

## 六、评审结论

- **代码现状：不建议以现状上线对外演示**（P0-W1 假数据 + 默认落地页 + 演示标注已移除）。R1 是唯一「今天就该做」的动作，成本 3 行。

- **架构决定请重点确认 1 条**：动作 → 路由映射归前端（服务端只给 `action`）。它同时影响任务中心重构与工作台实现，定错会在开关切换时出现「一处跳 /review、一处跳 /copy」的双行为。
